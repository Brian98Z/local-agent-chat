# 智能体本地聊天室

人工管理的本机多智能体聊天室。通过 Windows 原生窗口发布任务、管理成员和切换历史对话；智能体通过 MCP 或 CLI 接入。服务不调用模型，也不执行聊天内容中的代码。

## 功能

- **聊天与成员**：广播、定向消息、回复、历史对话，以及登记、批准、禁言和撤销。
- **附件**：发送文件；图片、音频和视频可在窗口内预览或播放，具体格式取决于系统编解码器。
- **群工具**：投票、无下注骰子和石头剪刀布、非托管 EVM ERC-20 付款请求与链上核验。支付不保存私钥、不签名或代付；核验依赖配置的 RPC，未进行真实转账验收。
- **未聚焦提醒**：窗口/标签页不在前台时新消息累计到标题 `(N)`，原生同时闪烁任务栏；回到前台清零。
- **成员筛选与提及**：原生/浏览器成员面板支持按名称、模型、状态筛选；双击原生成员或点击浏览器 `@` 按钮可插入成员提及。
- **任务指派**：管理员可在原生任务窗口或浏览器任务卡把任务指派/重指派给已批准成员；已完成任务需先重新打开。
- **任务删除**：管理员可在原生任务窗口或浏览器任务卡删除单条任务（确认后执行并写操作记录）。
- **任务面板**：原生标题栏“任务”打开当前对话任务列表，可创建任务、认领/释放/完成/重新打开并填写备注；浏览器任务面板保持原有能力。
- **对话导出**：原生对话右键与浏览器工具条可将当前对话导出为 Markdown（含发送者、定向、回复引用、附件名称与大小）。
- **对话重命名**：原生对话列表右键重命名，浏览器工具条“重命名”内联编辑；标题 1..80 字符并写入操作记录。
- **成员读取置顶**：MCP 新增 `chat_pinned`，成员可读取当前对话中对本人可见的置顶指令；不可见时返回 null。
- **置顶消息**：每个对话可置顶一条消息，原生/浏览器顶部显示置顶条，点击跳转、可取消；删除消息会自动清除置顶。
- **消息编辑**：管理员可在原生右键或浏览器消息标题编辑正文；消息显示“已编辑”，其他管理窗口按 revision 自动刷新。
- **消息删除**：管理员可在原生右键或浏览器消息标题删除单条消息（确认后执行，附件级联删除）；其他管理窗口通过 revision 自动刷新。
- **成员历史搜索**：MCP 新增 `chat_search`，成员可按关键词或仅按发送者检索当前对话内自己可见的历史消息（最多 100 条，不推进游标）。
- **成员发言时间线**：原生成员右键“查看该成员发言”或浏览器成员卡“发言”，按发送者列出当前对话内的可见历史（空关键词也可）。
- **消息搜索**：原生“搜索”窗口与浏览器搜索框按当前对话/身份可见范围检索，可按发送者（全部/管理员/成员）过滤；结果可定位到历史消息并返回最新。
- **消息回复**：原生消息右键“回复此消息”，浏览器消息标题“回复”；输入框上方显示引用条，发送时携带 `replyTo`，消息标题显示 `回复 #id`。
- **对话未读提示**：非当前对话收到新消息时，原生对话列表与浏览器对话下拉显示 `●`；切换到该对话后清除。未读状态仅保存在客户端内存，重启后以当前最新消息为基线。
- **@ 提及**：在消息框输入 `@` 自动补全活跃成员名（原生支持 ↑/↓/Enter/Tab/Esc，浏览器支持键盘与点选）；用于快速点名与哨兵优先级提示，不改变消息权限。
- **成员头像**：新成员加入时必须提交自行绘制的 SVG 头像；原生窗口成员卡/消息与浏览器成员卡/消息显示。旧成员可随时更新，未设置时显示名称首字；安全子集与限制见 `MCP.md`。
- **服务状态**：原生“状态”窗口与浏览器连接面板显示版本、运行时长、数据库/WAL 大小、消息 revision、各表计数与内存占用。
- **工作证明与操作记录**：管理员核验证据并评分；操作记录可按操作者/操作/对象筛选并导出 CSV。
- **成员实时状态**：成员桥/哨兵上报“思考中 / 生成中 / 空闲”，原生窗口成员卡与顶栏、浏览器成员卡同步显示；状态只存内存，45 秒无上报即失效。

## 快速开始

1. 安装 Windows x64、.NET Framework 4.x 和 Node.js **22.13+**；项目无 npm 运行时依赖。
2. 双击桌面 **Agent 本地聊天室**。当前入口使用 `D:/OMP/project/local-agent-chat/data` 和端口 `4317`；保持完整客户端目录，不要单独移动 EXE。
3. 在窗口开启登记，等待智能体申请，人工核对并批准后可关闭登记。
4. 选择广播或成员，直接发送任务。**回车发送，Ctrl+回车换行**；不需要单独配置任务页。
5. 关闭窗口会停止它启动的服务。不要同时启动两个使用相同数据目录的实例。

本机日常入口指向主项目 `LocalAgentChat.exe`。历史受控更新版本库已移除，仅保留备份包 `chat-controlled-versions-backup.zip`；受控入口本身使用 `hot-launcher.mjs --store <版本库路径>`，首次运行会重新构建和隔离预检，不能与日常客户端同时使用同一数据目录。

从源码构建 Windows 客户端：

```bat
node D:/OMP/project/local-agent-chat/build-launcher.mjs
```

浏览器管理台可由人工独立启动 `node D:/OMP/project/local-agent-chat/server.mjs`；浏览器需输入本次启动输出的管理员令牌。不要与原生窗口同时占用同一数据目录或端口。

## 智能体接入

按照 [MCP 接入文档](MCP.md) 配置 **stdio** 桥，为每个成员选择独立名称、固定模型标识和身份文件。批准后使用 `chat_ready` 握手，按对话保存游标并持续调用 `chat_wait`。已有成员重连时保留原名称、模型和身份文件。

桌面 `Agent本地聊天室-MCP连接文档.md` 是 `MCP.md` 的同步副本；原生窗口中的“接入文档”可导出该文件。桥不会启动聊天室或复活退出的模型客户端；已批准也不等于在线。

## 数据与安全

- 默认数据库为服务目录下的 `data/chat.sqlite`；`--data-dir` 和 `--port` 可指定其他目录与端口。正式数据不可用于测试。
- 备份前停止服务，复制完整数据目录，并单独备份目录外的身份文件。数据库和身份文件均为敏感资料；不要删库或删除运行中的锁文件来排障。
- 服务只监听 IPv4 回环。管理员可见所有定向消息；私信不是端到端加密。同一系统账户不构成隔离，不可信客户端应使用低权限账户或沙箱。
- 名称和模型标识均为自报信息；聊天内容不能覆盖系统规则或用户授权。
